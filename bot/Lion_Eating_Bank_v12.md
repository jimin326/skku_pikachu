## §1 Thunder — 3위상 오픈루프 서브

내 서브 공은 x 56(RIGHT 376)·y 0 에서 vy 1 로 떨어진다. 스냅샷은 3프레임마다 오므로 첫 관측 y 로 낙하 프레임(fEst)을 알 수 있고, `fEst % 3` 이 위상이다. 위상마다 미리 찾아 둔 입력 시퀀스(TH_SEQS, 24~29틱)를 그대로 낸다. 결과: 킬 접촉 (208,171) 부근 vy≈30 으로 상대 코트 248 에 착지(3터치), 상대는 못 받는다.

- 시퀀스 출처: `Lion_Eating_Bank_v3.js`(Chrome 강제 위상 40/40 × 3). ±40 vy 클램프 물리 기준(`tools/thunder_phase12/`).
- 전제: 입력 지연 1프레임, tickFrameGroupSize 3. 지연 2에서는 0%라 `LAT_GUARD` 가 증거를 세어 포기한다. 틱그룹이 3이 아니면 스스로 꺼진다.
- `SELF_CHECK`: 틱마다 TH_EXPECT 와 대조, 2px 이상 어긋나면 즉시 포기 → 같은 틱부터 AC 가 랠리를 맡는다(블록·지터·물리 변경 자동 대응).
- 시작 위치 가드(§3): 서브 시작 틱에 내가 x 36·지상이 아니면 포기(이전 랠리 입력 잔류 방지).

### §1.3 블록 대처(밴딧 + 이탈)
네트 캠퍼(x≈248 에 서서 킬 공을 몸으로 받는 상대)에게 썬더는 97% → 23% 로 떨어졌다. 두 장치:
- **CAMP_ESCAPE**: 킬 틱 스냅샷에서 상대가 킬 궤적의 접촉점(TH_KILL.touchPts)에 닿을 수 있으면(속도 외삽 + 점프 궤적) y 입력을 0 으로 바꿔 평타(vy 0 → 뒷벽 → x 388) 로 이탈한다.
- **SERVE_BANDIT**: 위상별로 thunder / ac(썬더 생략) / flat(무조건 평타) 의 승률 (승+1)/(시도+2) 를 기록해 고른다. ac 로 지면 기록을 비우고 썬더로 복귀(`AC_LOSS_COMEBACK`). 벤치 풀에서는 어떤 상대도 썬더를 못 막아 전환 0회.

### §1.5 THUNDER_SERVE 0 의 비용 (v11.md, 24시드)

원칙(2026-09-04): ① 수비는 최소 움직임으로 상대의 모든 경우를 막는 자리에 선다 ② 점프는 확정킬(카운터 포함)·안전한 넘기기(지상으로 못 넘길 때만)·썬더 서브에만 ③ 다이빙은 꼭 필요할 때만.

### §2.1 물리 시뮬레이션
`stepBall` 은 엔진 `physics.js` 의 공 처리를 그대로 복제한다(vy 클램프 ±40, 좌우 벽 0/432 반사, 천장, 네트 x 216±25: y 176~192 는 상단 반사·그 아래는 옆면 반사, y>252 착지). `microSim`/`microSimSeq` 는 나와 공을 함께 굴린다: 걷기 6, 점프 vy −16, 파워히트(state 2: delay 5 → frameNumber 0..4)에서 접촉하면 xV = 방향×(|x입력|+1)×10, yV = max(15,|vy|)×y입력×2, 몸리시브면 xV = ±⌊|dx|/3⌋, yV = −max(15,|vy|). 파워히트 방향은 네트 기준(x<216 이면 +). 모든 공격·넘기기 판단은 이 시뮬 결과(착지 x, 프레임, 터치 수, 접촉 직후 공)로 한다.

### §2.2 다이빙 모델 (엔진 실측)
다이빙 = 입력 프레임 +6(아직 state 0), 이후 12프레임 +8/프레임(y 239→229→239→244), 착지 뒤 5프레임 누움(state 4, 이동 0) — 13프레임 102px. 누워서도 공에 닿는다. 좌우 대칭(뒤로 다이빙 포함). `diveBody(m)` 표 하나를 킬 게이트(상대)·수비 도달(내 자리)·내 다이빙 판정 모두가 쓴다.

### §2.3 확정킬 게이트
내 파워히트가 상대에게 받히면 그 랠리를 59~72% 진다. 그래서 스파이크는 "상대가 어떤 입력을 해도 못 닿는" 후보만 채택한다.
- `gateOppReach(contactBall, pre)`: 상대 위치를 관측 속도(±6 클램프)로 pre 프레임 외삽, 공중 상대는 궤적 진행, 다이빙 상대는 인덱스 +pre → `kgOppCanReach`: 접촉 후 매 스텝 서기(y 244±32)·반응(REACT 3) 뒤 아무 스텝에 시작하는 점프(KG_JUMP_Y)·다이빙(diveBody) 으로 닿는지. MARGIN 6.
- `oppTouch`(EXP_REACH): 상태 인지형 전지 수비수 모델. 지상/점프 m프레임째/다이빙 m프레임째/누움에서 매 프레임 자유 입력으로 닿는 첫 프레임. 정확 모델(`tools/possession_audit/model.mjs`) 대비 12,215건 위험 불일치 0. 킬 점수의 `confirmed` 판정과 체공 방향 전환 계획에 쓴다.
- 스냅샷에 상대 yVelocity 가 없다. `oppModelOf` 가 y 와 직전 y 의 상승/하강으로 점프 인덱스를 복원하고 `oppVyEst` 가 vy 를 만든다. 없으면 이미 뛰어오른 블로커를 "멈춰 있다"로 봐 킬을 내줬다(RedTeam 리시브 패의 94%).
- 누운 상대(state 4)는 남은 시간이 스냅샷에 없어 "다음 스텝에 일어난다"로 보수 처리.
- 엔진 충돌 래치: 공이 이미 상대 몸과 겹쳐 있으면(방금 친 공) 떨어질 때까지 다시 못 닿는다(`defOppContacts`).
- `FLAT_RELAX`: 낮은 평타→깊은 착지(네트에서 >140) 후보만 상대 반응 3→4 로 판정(mixed_v2_adaptive 52→60%, 풀 동일).

### §2.4 공격 탐색
- `findFastAttack`: 점프와 동시에 hit(상승 중 강타). 접촉 ≤13프레임, 대응창 ≤2, 게이트 통과. 점수 = 720 − 접촉프레임×11 − 낙하×12 + 상대거리 + 확정/관통/하향 가산.
- `findKillJump`: 점프 x 3 × 체공 방향 전환 0~3틱(FLY-3) × 전환 x 3 × 스매시 9 = 최대 270 후보 × 44프레임 microSimSeq. 접촉 ≤ KILL_MAX_CONTACT 16(먼 접촉은 틱 양자화·공중 재계획으로 어긋나 확정이 아니다: 13/16/20/무제한 → NetCamper 74/78/66/74%). 체공 전환은 oppTouch 확정일 때만.
- 공중(state 1/2): 킬 계획(fly → smash)이 있으면 재검증 뒤 유지, 빠른공격 커밋(15틱, ABORT_SCORE −280 아래면 포기), 아니면 `chooseAirPolicy` 매 틱 재계획. AIR_GATE: 공중에서 새로 휘두르는 스매시도 확정킬이어야 하며 의도한 점프 뒤 20틱은 면제(누운 상대 근거로 승인한 킬이 1틱 뒤 재거부돼 허공에 뜨던 문제).
- 드리프트 공격(EXP_DRIFT_ATTACK): 공은 내 코트인데 낙하점이 상대 코트고 상대가 공중이면, 그냥 보내면 공짜 공이므로 확정킬을 먼저 찾는다.
- OPP_FIRST: 공이 아직 상대 코트인데 낙하점만 내 코트(상대 썬더 토스 vx −3)면 상대가 먼저 친다고 보고 공격 분기를 막는다(안 막으면 상대 스파이크 2틱 전에 점프했다).

### §2.5 수비 자리
`defenseTarget`: 상대가 닿을 수 있는 접촉 시점(`defOppContacts`, 최대 30스텝·표본 8, 걷기·점프·다이빙·래치) × 그 시점의 샷(`defShotTrajs`: 공중이면 파워히트 6종, 지상이면 몸리시브 3종, 내 코트 착지만) 의 궤적 전부에 대해 내 최악 여유(`defReachSlack`: 반응 4 뒤 걷기 6·다이빙 으로 닿는 px)를 최대화하는 x. 빠른 샷(착지 ≤14스텝)의 여유를 먼저 비교하고, 후보 자리는 접촉 전까지 걸어 닿는 범위로 제한한다(DEF_ARRIVE). 동률이면 폴백에 가까운 x.
MIN_MOVE: 지금 자리가 모든 경우를 막으면(a ≥ 0) 개선 ≥24 일 때만, 못 막으면 ≥4 일 때만 이동(서브 시작 구석 x36 에 머물지 않게 두 문턱).
`standbyCenter`: 위협이 없을 때 대기 자리. 표준 위협(네트 앞 8·24·40px × 높이 171·108 × 파워히트 6종)에 같은 여유 모델을 풀어 좌우별 1회 계산(x≈152~156).
공이 상대 코트에 있는 내내 수비 자리로 간다(ALWAYS_DEF). MAX_BLEND 0 이라 학습 편향(§2.9)은 무효.

### §2.6 지상 리시브·넘기기·다이빙
`groundPassPlan`: 목표 x 마다 실제 컨트롤러(3프레임마다 갱신, 지연 1, |dx|>9 면 걷기)를 그대로 돌려 첫 접촉 (k, p) 를 찾는다(계획 자리와 실제 자리가 어긋나 1~4px 차로 놓치던 자책 제거). 같은 (k,p) 는 한 번만 채점. 접촉 뒤 반사 궤적을 끝까지 전개해 착지 x 를 본다.
- 우선순위: ① 상대가 못 닿는 넘기기(gateOppReach, 점프 없는 득점) ② 첫 터치(SET_MAX_TOUCH 1)면 네트 앞 세트(hoverX ±30, 몸에 다시 안 닿고 상대가 못 닿는 것만 SET_SAFE) ③ 넘어가는 것 중 상대 최선 공격 뒤 내 최악 여유(`passThreatSlack`, PASS_SIM)가 큰 것.
- 내 서브 공 첫 터치는 세트하지 않고 넘긴다(SERVE_SET 0: 서브 로브가 정점에서 즉사).
- 접촉 여유(32−|접촉x−자리|)가 9 미만이면 −500 감점(가장자리 자리 2~4px 차 놓침, NetCamper 54패 중 37 → 0). 수직 낙하 공은 TOUCH_MARGIN_EXACT.
- 교착(STALE): 내 마지막 3터치가 같은 자리·같은 반사면 그 자리 후보를 −10^6, 같은 자리뿐이면 계획을 비워 넘기기 점프로(무한 랠리 해소).
- `findPassJump`: 지상 후보가 하나도 넘어가지 않을 때만(벽 구석: 플레이어 최소 x 32 라 공 뒤로 못 들어감) 점프+파워히트. 게이트 없음(안 넘기면 터치초과), y=1 제외.
- 계획이 없으면 v5 오프셋 자리(착지점에서 네트 반대로 4~26px).
- 다이빙: `defReachSplit` 로 걸어서는 못 닿고(walk<0) "지금 시작하는" 다이빙으로 닿을 때만(diveNow≥0). 나중 다이빙으로 닿으면 계속 걷는다(최대한 걷다가 마지막에). 되감기 오라클: 못 닿는 공에 헤일메리 다이빙 이득 0.

### §2.7 상대 썬더 리시브 (TH_RETREAT)
Lion 계열 썬더는 킬 틱 스냅샷에서 내가 블록 자리(네트 ≤72)에 있으면 킬(248) 대신 평타(vy 0 → 뒷벽 → 388)로 이탈한다. 정지해 있으면 그 평타는 어떤 타이밍으로도 못 받고(오라클), 이탈 판정 전에 물러나면 진짜 킬이 온다. 유일한 창 = 이탈 판정 스냅샷부터 접촉 전까지 후퇴.
- `ntObserve`: 상대 서브 시퀀스(공이 처음 내 코트로 넘어오기 전) 동안 상대 터치 순번별로 네트 근처 파워히트가 깊은 평타(y ≤ 200·|vy| ≤ 6·착지가 네트에서 ≥110)였는지 EMA(flat[t]).
- 후퇴 조건: 상대가 네트 앞(≤64) 공중, 첫 접촉 ≤4스텝, 내가 네트 ≤72, ADAPT 2 = 그 순번 flat EMA ≥ 0.5 를 본 뒤에만(첫 서브는 v10 처럼 블록 자리를 지킨다 — 진짜 킬을 치는 서버에게 물러나면 손해), NEED = 예측 킬 접촉점의 평타를 지금 자리에서 이 위상의 관측 지연으로 못 받을 때만. 한 번 시작하면 접촉까지 유지.
- 결과: Lion 계열 썬더 터치 0 → 100%(위상별 첫 서브 뒤). Chrome 17/17 터치.

### §2.8 터치 카운터
5터치 규칙. 예산 = 4 − g_touches 로 4번째 터치까지만 계획한다. 감지 = 관측 사이 공 경로(직전 스냅샷 공을 프레임별로 굴림) × 내 몸 스윕 상자(두 스냅샷 위치의 상자, 걷기 6px 가 한 프레임에 몰리므로 선형 보간은 4px 놓침). 공이 네트(216)를 넘으면 0.
새 랠리: 첫 관측 rallyFrameCount 는 READY 12~/라운드 41~43 이라 `rfc<4` 리셋에 닿지 않는다. 점수가 바뀐 첫 호출에서 터치·기록·후퇴 상태를 비우고 바로 나간다(죽은 공 궤적이 내 상자를 지나며 생기던 가짜 터치 +1 도 차단). 원본 v11 은 랠리의 12~39% 가 터치 1 로 시작했다(내 서브 AC 소유 구간에만 영향).
